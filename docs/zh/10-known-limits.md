## 10. 已知限制

1. **`safety_check` 没有「关闭」档**：不传等同于 `low`，这是 API 的最低档，服务端仍有默认检查。
2. **服务端对齐依然存在**：模型判定的拒绝（`stop_reason: 'refusal'`）无法由前端取消；防撤回只能保留已经流式发过来的部分，不能让模型继续生成被拒内容。
3. **历史轮次的思维链不回传**：按协议，历史 thinking 会被服务端丢弃，客户端也不回传。所以改写思维链影响的是「界面显示 + 续写前缀」，普通后续轮次只有正文生效。
4. **思考模式下采样参数受限**：服务端固定温度按 1 处理，Top P 小于 0.95 会被按 0.95 处理。
5. **`max_tokens` 含思考 token**：设置过小可能连思考一起截断。
6. **改写只作用于本地上下文**：不重新请求模型，也不会改变服务端已有的输出；导出的归档里保存的是改写后的内容，原始快照不写入归档。
7. **附件限制、密钥校验、语音接口**仍走原版逻辑，与本文档的开关无关。
8. **越狱实验台不是纯静态能力**：需要本地 Python + MCP 后端（`mcp-server/`），且一次任务会发起大量模型调用，请先用 `limit=1` 和小迭代次数试跑。
9. **自定义提示词会覆盖自动组装**：填写后越狱模式不再替换 `system`，但仍会跳过安全审核、放开被拒续写；清空输入框即可回到默认流水线。
10. **长对话压缩会丢细节**：摘要有损，自动压缩按窗口 80% 触发（1M 窗口约 80 万 token 才触发），日常建议用统计弹窗手动压缩；会话级系统提示词与压缩摘要只存在本机会话里，历史导出包不含它们。
11. **分支到新对话复制的是当前可见分支**：不包含其他回答版本，也不复制草稿；附件沿用原 file_id；新会话的统计从 0 开始，继承来的用量不计入。
12. **恢复默认设置保留 API Key**：只重置偏好与开关，不删除对话、附件与统计。
13. **自动越狱与变体赛跑会产生额外费用**：每次重试、每个变体都是真实请求，变体赛跑受预算上限约束。
14. **云端模型列表依赖 API 与网络**：拉取失败时回落到内置两档；未收录到价格表的模型按 Flash 价估算、上下文窗口按 128k 兜底，实际能力以服务端为准。
15. **切换模型不回溯旧回复**：旧回复保留原模型与费用；续写沿用该回复的模型，只有新回复使用当前选择。
16. **自动提炼长期记忆会产生额外调用**：每轮一次 Flash 请求；长期记忆与记忆库只存在本机，历史导出包不包含。
17. **记忆库向量是本地哈希向量**：不是语义 embedding，检索效果有限但无需外部服务；调整向量维度后按新维度重新计算。
18. **每日用量只统计聊天回复**：MCP 实验台、赛跑、标题生成等独立调用不计入；费用按当前峰谷价估算，与服务端账单可能有细微差异。
19. **自定义位置与特殊位置只影响 latest_reminder**：不会改变天气、联网搜索或服务端区域判断。
20. **历史思维链伪装只处理上一轮**：以普通正文形式下发，服务端不会再按 thinking 处理；开启后 token 会略微增加。
21. **关系图最多绘制 80 个节点**：超出部分不绘制，但检索仍覆盖全部节点；导入「覆盖」会替换当前长期记忆与记忆库，操作前可用导出备份。
22. **流式输出开关只控制界面渲染**：关闭时仍使用 SSE 接收并完整累积回复，只是不展示中间态；页面隐藏/关闭时会把已累积内容写回，避免丢失。
23. **搜索投毒不是服务端代理**：服务端搜索在服务端执行，客户端拿到的结果已经是模型本轮看过的内容；关闭接管时只能改写展示，不能撤回本轮结果。
24. **接管搜索依赖自定义结果**：没有自定义结果时不会自动关闭服务端搜索（黑名单 / 白名单除外）；接管后模型只能看到配置结果，真实搜索不会执行。
25. **自定义时间 / 知识截止只是提示**：只影响 `latest_reminder` 与注入上下文，不改界面、计费、天气或服务端区域判断；模型也不一定完全遵守知识截止。
26. **附件投毒只影响新上传 / 重新上传**：已发送的附件服务器文件不会重写；输入框里有本地原件的附件会在下一次发送时按当前配置重新上传，导入且没有原件的附件保持原样，已发送历史附件不重写。
27. **客户端改写是尽力而为**：图片文字覆盖需要 Canvas，PDF 文件尾与图片元数据是实验性方式，不保证模型一定读取；PDF / Office 建议优先使用伴随文本附件。
28. **伴随文本附件占用附件名额**：名额不足时不会生成；恢复默认只清理本机配置与草稿中自动生成的伴随附件，不删除服务器或历史附件。
29. **图片文字覆盖会重新编码**：GIF / 动图会变成静态图，GIF / BMP 等可能转为 PNG；文件尾附加对 ZIP 类 Office 文件自动跳过。
30. **APK 内的 Python 后端不会执行**：EasyJailbreak / torch 依赖无法放进普通 WebView APK；后端源码只随包附带，实验台必须连接电脑或服务器上的 MCP 服务。
31. **APK 是 WebView 壳**：文件下载等浏览器能力取决于系统 WebView；本地服务固定占用 18765 端口，被占用时应用会显示启动失败提示。
32. **自定义思维链是提示词引导，不是真正的 reasoning 通道**：关闭深度思考时，回复上方卡片展示的是你预设的步骤，不是模型实时推理；模型也可能不完全遵守；每轮都会增加输入 token，正文上限 4000 字符。
33. **开启深度思考时自定义思维链是实验性**：服务端 thinking 优先，可能忽略或重写这些步骤，不保证与直接注入同样效果；此时不重复显示「已注入思维链」卡片，以服务端 thinking 为准。
34. **自定义思维链只作用于聊天请求**：多路赛跑、变体赛跑、长对话压缩、记忆提炼等独立调用使用各自的系统提示词，不读取该设置；聊天首轮同时生成标题，仍会注入。
35. **「已注入思维链」卡片只保存在本机会话**：历史导出包不含该展示字段，重新导入后不显示；续写沿用原回复快照，重新生成使用当前设置。
36. **浏览器工具受浏览器能力限制**：抓网页受目标站点 CORS 限制；通知、定位、剪贴板需要权限，APK 的 WebView 里通知通常不可用（自动标注并禁用）；「打开链接」可能被弹窗策略拦截。
37. **工具往返按轮计费**：一轮回复最多 4 次工具往返，每次都是真实请求，token 与费用按轮累加；关闭主开关后模型完全看不到工具。
38. **NanoVM Slim 是浏览器内的模拟环境**：不是真正的 Linux 内核，没有进程隔离、没有多用户权限、也没有信号与作业控制；`&` 后台执行不保留，`kill` / `nice` / 设备文件都不可用。文件与配额只在本机，清站点数据会一起清掉。
39. **busybox 命令是子集实现**：`awk` 不支持 `printf` / 数组 / 循环 / 自定义函数，`sed` 没有 `{}` 块与 `r/w/l` 命令，`sort -h/-M/-V`、`grep -A/-B/-C`、`find -mtime/-size/-perm` 等未实现；不支持的用法会**明确报错**而不是静默给出错误结果。
40. **`npm` / `pip` 不可用**：Node.js 是浏览器里的兼容运行时（`fs` / `path` 子集 + Web Worker），Python 是 Pyodide（WASM CPython，纯 Python 包可用、C 扩展需 Pyodide 内置支持）；装真实依赖请用宿主环境的包管理器。
41. **`curl` / `wget` 受 CORS 限制**：只能访问允许跨域的目标；失败时会明确说明是网络、CORS 还是 HTTP 状态码问题，不会伪装成功。
42. **虚拟机里的脚本就是新命令**：`chmod +x` 后的脚本可以按路径或 `$PATH` 直接执行，shebang 支持 `sh` / `bash` / `python3` / `node`；没有 shebang 会按 Linux 习惯报 `Exec format error`。副作用是 `exit 3 | cat` 会结束整个脚本（管道阶段不是真进程），而不是只结束管道里的子 shell。
43. **工具链第一次安装需要联网**：Python 约 12MB（Pyodide），装完缓存在本机、之后离线可用；Node.js 与 Git 是内置实现，不需要下载。Git 只支持本地仓库，没有 `clone` / `push` / `pull`。
44. **工作区容量**：OPFS 模式按 `navigator.storage.estimate()` 的配额动态计算（最多 80%，上限 64GB 总量 / 256MB 单文件），配额越大可用越大；localStorage 模式无法扩容（通常 5–10MB，base64 还会放大约 1/3），写满会明确提示切换到 OPFS。清空或覆盖导入前请先导出 ZIP 备份。
45. **工作区不随历史导出**：历史导出包只含会话与图片，工作区与工具卡片都不在其中；换浏览器或清站点数据会丢失工作区。
46. **OPFS 与持久化权限因浏览器而异**：老 WebView / 隐私模式可能不支持 OPFS，此时只能留在 localStorage；`navigator.storage.persist()` 也可能被拒绝，未获授权时浏览器仍可能在空间不足时清理数据，重要内容请导出备份。
47. **切换存储方式会整体覆盖目标后端**：切到 OPFS 会先用当前内存里的文件覆盖 OPFS 目录，切回本地则覆盖 localStorage 副本；切换前建议先导出。
48. **上下文分类是估算**：按字符权重计算（中文 1 字 1 token、其余 4 字符 1 token），与服务端计费口径可能有差异，准确用量以 KPI 区服务端上报数字为准。
49. **聊天模式只影响客户端工具**：服务端工具（读链接 / 联网搜索）在四种模式下都一样下发，`仅聊天` 不会关掉它们；模式是全局选择（`chat-demo:chat-mode`），不随会话保存。
50. **PTC / 创造模式会并发执行同一轮的工具调用**：多个需要确认的工具排队逐个弹窗；创造模式对 NanoVM 工具免确认，模型写错路径、删错文件或装错运行时的代价由用户承担，建议先在不重要的会话里试。
51. **同一轮里的工具调用会共享一份终端用量**：并发执行的多个 NanoVM 命令都算在同一条回复的工具往返里，费用与上下文按轮累加。
52. **虚拟机没有真正的 ICMP 与 DNS**：`ping` 是 HTTPS 探测（`HEAD` / `GET` 计时），目标不响应 HTTP 不代表主机不可达；也没有 `nslookup` / `dig`。
53. **联网绕不过浏览器安全模型**：APK 里的内置代理只服务本应用（token 校验、只监听 127.0.0.1），普通浏览器仍然受 CORS 限制；自定义代理会把目标 URL 发给第三方，请自行判断是否信任。
54. **新增工具链同样需要联网**：Lua（wasmoon，约 0.4MB）、SQLite（sql.js，约 1.3MB）、esbuild（esbuild-wasm，约 12MB）首次安装从 jsDelivr 下载，装好后缓存复用；`make` 是内置实现，不需要下载，装完即可离线用。
55. **运行时能力都是子集**：esbuild 只能打包虚拟机里的文件（不解析 npm 依赖、没有插件生态），SQLite 是 sql.js（没有 FTS / 扩展模块），Lua 没有 `os.execute` / `io.popen` 这类宿主能力，`make` 不支持并行构建、`$(call)` / `$(eval)` 与目标专属变量，`jq` 只覆盖常用过滤器；`timeout` 到点返回 124 但**不能真正杀掉**子命令。
56. **虚拟网络是 CGI，不是真 socket**：`vm serve` 注册的服务每次请求都重新跑一遍命令（冷启动），没有常驻进程、keep-alive、并发与长连接；请求体和响应都整体缓冲，`curl` 之外的程序访问不到这些端口；服务里再请求自己嵌套超过 3 层会被拒绝。
57. **Go / Rust / C / C++ 没有浏览器内编译器**：官方工具链都不提供能在浏览器 WASM 里跑的 `go` / `rustc` / `gcc`，所以 NanoVM 不伪造它们。写后端可以用 Node（`http` / `ws`）或 Python（Flask / `nanovm` 微框架）挂在虚拟网络上；真正需要 Go / Rust / C 的二进制，请在宿主机上编译后再把产物或接口接进来。
58. **WebVM 需要跨源隔离**：CheerpX 依赖 `SharedArrayBuffer`，页面必须带 COOP/COEP。静态站点第一次启用时注册 `coi-sw.js` 并刷新一次；`file://`、局域网 HTTP（非 localhost）以及禁用 Service Worker 的浏览器都无法启用。开启后同源的第三方 iframe / 跨域图片可能受 COEP 影响（用 `credentialless` 降低影响），遇到嵌入内容空白可先关闭 WebVM。**Android WebView 至今不支持跨源隔离，所以 APK 内无法运行 WebVM**，请用手机 Chrome 或桌面浏览器打开在线版。
59. **WebVM 首次启动要联网拉约 2GB 镜像块**：CheerpX 运行时来自 `cxrtnc.leaningtech.com`，根文件系统来自 `disks.webvm.io`；首启通常 30–90 秒，慢网更久。之后从 IndexedDB 覆盖层缓存启动，但清站点数据、换镜像或重置都会让缓存重新下载。
60. **WebVM 是 32 位 x86 的 Debian 10**：软件包停留在 buster 时代，没有 `npm`（只有 `node`），没有 `apt` 网络，也没有 Tailscale；需要新版本工具链、原生扩展或包管理时，请用 NanoVM、宿主环境或自己的自定义镜像。
61. **一个 WebVM 只有一个控制台**：这与 NanoVM 的多标签不同。NanoVM 与 WebVM 可以同时运行，但 WebVM 内部只有一个 bash；模型命令复用同一个 shell 串行执行，所以用户正在跑前台命令时，模型命令会排在后面甚至超时，Ctrl+C 也可能同时中断两边。
62. **WebVM 导入导出有上限**：单批最多 50 个文件 / 20MB；导出是 `/home/user` 的 tar.gz（base64 捕获，上限 32MB），不是整块磁盘镜像。重置会清空 IndexedDB 覆盖层，VM 里新建与修改的文件全部丢失。
63. **WebVM Agent 工具首调最长 5 分钟**：首次启动要等镜像块，工具超时按 5 分钟计；启动后的命令通常几秒。超时只保证工具返回，已经启动的命令仍可能在 VM 里跑完，输出会回到终端。
64. **CheerpX 是专有软件**：Leaning Technologies 允许个人与开源项目免费使用，商业使用需要商业许可；运行时与默认镜像由他们的 CDN 提供，是否可接受这种依赖由部署者判断。
65. **两个虚拟机不共享文件系统**：NanoVM 的 zip 镜像与 WebVM 的 tar.gz 不互通，需要手动解包后再导入；`/home/user` 也是两套独立目录，模型要明确自己在操作哪一个 VM。

66. **关键词拒答是本地子串匹配**：只检查用户文本，不检查附件、图片文字或模型输出，也不做语义审核；中文不分大小写，英文关闭「区分大小写」时统一转小写。命中后不请求接口、不触发搜索与工具，但也不会阻止用户换一种说法绕过。

67. **WebVM 的 root 是镜像内的密码式提权**：`sudo` 通过镜像自带的 setuid `su` 实现，root 密码固定为 `password`，不是真正的 sudo 包；它只改变虚拟机内的权限，不涉及宿主机。非交互脚本 / Agent 命令里的 `sudo` 会等待密码输入，可能超时，建议在终端里手动使用或点 Root 按钮。

68. **本地模型需要 WebGPU**：浏览器模型走 WebGPU，`navigator.gpu` 不存在或拿不到适配器时只能改用 MLC-LLM API；Android WebView 没有 WebGPU，APK 内同理。软件渲染（SwiftShader）通常没有 `shader-f16`，q4f16 模型会加载失败，只能选 q4f32 或换真实 GPU。

69. **模型权重来自外网**：WebLLM 的模型库与权重分别在 GitHub Raw 与 Hugging Face 上，网络受限时下载会失败；已下载的模型不受影响，可以用 `.mlcmodel` 换机导入。

70. **浏览器存储配额有限**：1B 级模型约 0.7–1GB，8B 级要 4–5GB；配额不足时下载会中断，建议只保留一两个常用模型，或改用 IndexedDB / 清理旧模型。

71. **本地模型只吃文本**：附件、图片、服务端联网搜索与客户端工具都不下发；需要这些能力时切回云端模型。

72. **导出体积等于缓存体积**：`.mlcmodel` 不做压缩（权重已压缩），导出 4GB 模型就会写出 4GB 文件；不支持 File System Access 的浏览器会先攒在内存里，大模型可能失败。

73. **MLC-LLM API 需要自建服务**：本项目只做客户端，服务端要自己用 `mlc_llm serve` 启动；服务地址与模型列表不做鉴权，跨域需要服务端允许。

74. **本地模型联网搜索要 API Key**：搜索是生成前的服务端预检索（DeepSeek Flash + 服务端搜索），没有 Key 时本轮只跳过搜索并提示，不会中断本地对话。

75. **本地模型附件只读文本**：txt / md / csv / json / 代码等按纯文本注入，单条 8K、总量 24K 字符，超出截断；图片与二进制附件跳过并提示，需要图片请切回云端模型。

76. **角色与我的资料只存本机**：`chat-demo:roles`、`chat-demo:profile-*` 不进入历史导出包，换设备需重新创建；角色提示词会进入 system，可能明显改变回答风格。

77. **本地模型只允许仅聊天模式**：Agent / PTC / 创造置灰不可选，搜索是预检索而不是模型自己调用工具；需要工具时请切回云端模型。

78. **提示词与思维链预设只存本机**：每类最多 30 套，存储键为 `chat-demo:system-prompt-presets` / `chat-demo:cot-presets`，不进入历史导出包；删除当前预设会清空当前提示词内容。

79. **NanoVM 单文件导入有上限**：单文件硬上限 256MB，磁盘配额最高 2048MB；导入会先扩容再写入，超大文件在 OPFS 上落盘要按 base64 序列化整个文件系统，可能需要几秒到几十秒，期间不要关闭页面。
80. **PyBot 启动不是即时的**：每次提问都要把约 39MB 源码同步进 Pyodide 并导入 528 个模块，实测约 8 秒；安装需要 Python 工具链（约 12MB），离线快照固定为提交 24cbc04，更新需重新打 `public/pybot.zip`；交互会话期间终端输入按聊天消息处理，要执行 shell 命令先 `/exit`。
81. **V4 Pro 缺少联网与图片能力**：服务端明确拒绝 `deepseek_web_search` / `deepseek_read_url` / `title` / `latest_reminder`。本项目为 V4 Pro 去掉这些字段、把日期提醒与压缩摘要折进 system、用首问生成标题并停用智能搜索；图片输入不会报错，但模型看不到图片内容。需要联网、联网标题或看图时请切回 DeepSeek Flash。

82. **Unkernel 需要 JSPI，Alpine / Debian 双镜像**：内核依赖 `WebAssembly.Suspending` / `promising`（Chrome / Edge 137+、Firefox 153+、Safari 27+）；旧 Android WebView 会显示启动错误，请用新版浏览器打开在线版。同时打包 Alpine（3.9 MiB）和 Debian（70 MiB），加上 DSH go 的 24 MiB 二进制，APK 约 112 MB；Debian 首次启动会流式读取 70 MiB 镜像。多 CPU 需要跨源隔离：桌面静态站点会提示开启并刷新一次，Android WebView 不支持，只能 1 个 CPU。联网默认走公共 Wisp 代理（anura.pro / mercurywork.shop，代理运营方能看到 guest 连接的主机名、端口和明文 HTTP 内容；TLS 仍是端到端）。如果公共代理不可用，在 设置 → Unkernel Linux 里填自己的 `wss://` 地址。DSH go 演示是 24 MiB 的静态 aarch64 二进制，Alpine 和 Debian 都能跑，不再需要 2 GiB 内存或 600 MB 运行时；首次运行在终端里输入 API Key（不回显），保存在 `~/.dsh-go/api-key`。数据盘可在 设置 → Unkernel Linux 里扩容或一键重置，重置会清空 `/data` 和保存的虚拟机快照。NanoVM / WebVM 的 `fastfetch` 是内置命令。全屏页面 UI 已汉化（终端里 Linux 内核自己的输出仍是英文）；应用内的设置栏和 Agent 工具也是中文。

83. **桌面端只是一个壳**：`src-tauri/` 用 Tauri 2 开一个窗口加载同一份 `dist/`，不新增功能，也不向前端暴露 Tauri 接口；没有托盘图标、应用菜单、自动更新和原生代理（NanoVM 联网只能直连或填自定义代理）。数据存在 webview 自己的 localStorage / IndexedDB 里（Linux 在 `~/.local/share/com.xiaohuangbo.deepseekunrestricted/`），和浏览器里在线版的数据互不相通，需要重新填写 API Key。

84. **桌面端不弹权限询问**：浏览器里麦克风、通知、定位第一次使用时会询问；桌面壳把麦克风、剪贴板读取、通知、定位直接放行，其余权限沿用各平台默认行为。这些能力只在对应功能用到时才申请：语音输入、终端粘贴，以及默认关闭的通知 / 定位 Agent 工具。

85. **Linux / macOS 桌面端拿不到跨源隔离**：`tauri://localhost` 不是标准协议，WebKit 不会为它建立跨源隔离，`tauri.conf.json` 里配的 COOP / COEP 不起作用（Windows 的 WebView2 把 `http://tauri.localhost` 当普通来源，配置生效）。依赖跨源隔离的 WebVM（CheerpX）和多 CPU 的 Unkernel 因此无法启用；Linux 的实测环境是 Debian 13 / WebKitGTK 2.52.6，macOS 同为 WebKit 内核，未单独验证。

86. **Linux 桌面端的能力取决于发行版的 WebKitGTK 构建**（Debian 13 的 2.52.6 实测）：没有 `SharedArrayBuffer`，WebVM 无法运行；没有 JSPI，Unkernel 依赖的 `WebAssembly.Suspending` / `promising` 不存在，无法启动；没有 WebGPU，浏览器内本地模型不可用，改用 MLC-LLM API；没有 `navigator.storage`，工作区的 OPFS 标签置灰，只能用 localStorage 模式（单文件 4 MB、总量 5 MB、200 个文件）。换用启用了这些特性的 WebKitGTK 构建，结果会不同。
